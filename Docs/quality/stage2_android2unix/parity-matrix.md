# TUI, Headless, Android Parity Matrix

The Rust owner remains the sole state machine. Android sends typed remote
requests and renders projections; it never executes provider, shell, or PTY
work locally.

| Surface | Read path | Write path | Authority boundary |
| --- | --- | --- | --- |
| Desktop TUI | Local owner projection | Local owner command | Existing owner thread |
| Rust headless host | TLS response/event projection | Durable request admission | `HostAdapter` / mailbox |
| Android | TLS snapshot/replay/subscription | Typed CAS or admission receipt | Device ACL + project/session scope |

Required parity cases are: same project/session identity, stale revision,
simultaneous local/remote mutation, one-use request retry, unknown outcome,
subtab stable IDs, approval digest, and replay cursor reconciliation.

## Evidence Boundaries

The remote_parity target has five tests covering captured directory/worktree
execution, root restoration after failure/unwind, unsafe root replacement,
selected-directory shell ownership and local model/reasoning changes while a
phone follow-up is pending. It does not by itself cover Android controls,
physical transport or the complete simultaneous-client matrix.

remote_subscription_tls uses real rustls encryption over bounded fragmented
in-process pipes. It tests the production subscription dispatcher, not the
production TCP listener or Android TLS implementation. remote_host_e2e has
three ignored live-listener tests and two ordinary provider-fixture tests;
the ordinary target passing cannot prove the ignored production workflows.
remote_frame also has one ignored real-loopback timeout test.

Several owner/worker tests construct controlled local or Echo backends to
exercise admission and state transitions. They do not demonstrate live provider
behavior merely because they invoke a production dispatcher. Real filesystem,
Git and PTY effects establish those host-side boundaries only. Test targets must
be reported separately from connected Android and production binary receipts.

The full matrix still requires current connected Android, physical camera/LAN,
production listener and lifecycle receipts before acceptance. No row is accepted
from a suite count or source compilation alone.
