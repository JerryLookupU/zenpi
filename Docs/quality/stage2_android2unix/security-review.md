# Stage 2 Security Review

Provisional review at 2026-10-03. This document records the security boundary;
it is not a release sign-off. The authoritative blueprint remains unchecked
until the live LAN, signed APK, and connected-device gates have run.

| Threat | Boundary / control | Evidence | Residual risk and release condition |
| --- | --- | --- | --- |
| QR invite copied or replayed | 256-bit one-use token, expiry, SAS, fingerprint and device proof; host consumes only a valid signed pair | `remote_pairing`, `PairingHandshakeTest`, strict URI/frame validators | A copied invite is usable until expiry. Keep the QR visible only during explicit pairing and invalidate it after a failed/finished attempt. |
| Camera payload normalization bypasses invitation input limits | Feed decoded QR text unchanged into the strict invitation parser; reject raw controls, surrounding whitespace and oversized padded payloads before confirmation | PairingInviteTest raw payload negatives; ScannerResultTest production callback/store assertions and mandatory scanner_raw_payload_fence_verified phase | Instrumentation source compilation is not device execution. Current APK/camera/direct-LAN acceptance remains required. |
| Cold-start invitation queue retains unvalidated input or renews expiry on restore | Validate before queuing; retain only one bounded PairingInvite with the original monotonic admission deadline, recheck freshness after metadata restore and preserve durable pending-request fences | ScannerResultTest queue identity/malformed replacement/observed expiry source regressions; mandatory cold_invitation_validated_queue_verified and cold_invitation_expired_queue_verified phases | Connected execution remains required. Removes the raw-string queue reference, not caller/system URI history or JVM memory; an already-expired queued invitation never initiates pairing. |
| Completed pairing keeps a consumed QR invitation in live screen state | After verified registration and local host save, publish saved host identity without the invitation; registration UX does not depend on token-bearing state | PairingScreenTest accepted/connected UI assertions; PhysicalQrHostTest production callback and mandatory physical_qr_invitation_retired_verified phase | Removes the state reference, not a guarantee of JVM memory erasure or Android Intent scrubbing. Failed/unknown pairing remains diagnostic; current connected/physical execution required. |
| Pairing URI remains in Activity task intent after admission | Copy the incoming intent without data before Activity/saved-state observers or ViewModel admission; preserve routing/action/type/extras, admit initial URI only on a fresh create and new URI once per callback | PairingActivityIntentTest delivery/single-owner/in-flight assertions plus cancel/recreate/no URI/no generation advance, mandatory external_pair_intent_consumed_recreation_verified phase | Removes local Intent data reference only, not extras/ClipData, sender/system history or JVM memory; device execution and process-death gates remain required. |
| Host impersonation | TLS 1.3, ALPN `zenpi/1`, pinned certificate SHA-256 DER and challenge signature | Rust TLS/pairing tests; Android transport validators | Physical-LAN and certificate-mismatch tests still require a real device/network. No release sign-off without them. |
| Malformed build receipt presents false/float as successful exit status | APK and host provenance require an integer exit_code equal to zero; JSON false, true, floating zero, string zero and null refuse even with matching source/artifact hashes | BuildProvenanceTests and HostBuildTests non-integer status negative matrices | Local provenance is attribution, not cryptographic build attestation or device acceptance; signing/install/current physical LAN gates remain required. |
| Host identity file substitution or startup denial | Private owner-checked regular file, no-follow/non-blocking Unix open, exactly one hard link; invalid files never replaced | `remote_pairing` hard-link/directory/FIFO regression and unchanged-byte checks | Parent-directory ownership and supported-host filesystem deployment require operator review; do not share or alias the active private key file. |
| Stolen device identity | Android private key remains in Keystore; host registry scopes capabilities and projects; revoke/self-revoke fences requests | auth, revoke, ACL and Android storage tests | A live unlocked device can use its granted capabilities. Operators must revoke lost devices and verify the committed receipt. |
| Physical self-revoke UI claims success without a durable host record | Correlate the phone-observed pending UUID with independently read device registry record; require revoked=true, exact next revision and retained ACL, alongside phone key/cache removal | PhysicalQrHostTest production UI source; v7 physical verifier/negative matrices | Prepared only, not current phone/Keystore/LAN execution. Post-send failure remains unknown; never infer host revocation from local forget alone. |
| Cancelled revoke completion deletes a key after identity-lock/Keystore wait | Direct and reconciled completion share coroutine/generation admission inside expected-device wipe; checks bracket public identity read and run before deleteEntry | DeviceRevokeTest real-key admission/blocked-lock source and required lifecycle named gate | Instrumented compilation only; connected execution required. Cancellation after admitted deleteEntry cannot promise rollback, and external Keystore changes are not an atomic transaction. |
| Replay or cross-project write | Request IDs, durable fingerprints, owner/session/project binding, CAS revisions and unknown-outcome state | `remote_workspace`, worker/admission and receipt tests | A transport disconnect can leave outcome unknown; never blindly resubmit a write. Reconcile by the exact request identity. |
| Retired recovery/preparation lease remains held through a fork-inherited descriptor | All worker leases explicitly unlock on Drop, including preparation failures and local recovery probes; a retired descriptor close cannot unlock a replacement writer | Deterministic dup-descriptor recovery/preparation and last-worker tests; worker-owner/concurrency/worktree/workspace regressions | Supported-host locking/filesystem and connected Android recovery still require acceptance. Existing parallel extension startup failures remain distinct. |
| Authorization changes after committed write before receipt delivery | Null-result coded unknown outcome preserves ambiguity and pending identity; typed authority codes remove old controls, Busy does not falsely revoke; coded steering stops polling | Shared Rust listener delivery_refusal security frame test, WorkspaceUnknownOutcomeTest and committed workspace/Kotlin interop | Actual production TCP/Android encrypted-intent/direct-LAN delivery race remains required; fixture envelopes do not establish that runtime race. |
| Subscription owner race hides a newer authorization refusal | Metadata/replay owner-mismatch rechecks preserve explicit unauthorized/revoked-device and authorized session-change codes; inconclusive samples retain owner-mismatch without publishing sampled data | remote_subscription two-path authority/inconclusive matrix and current Rust-frame Kotlin response/policy regression | Controlled dispatcher samples are not a production registry/TCP race; actual device revocation and LAN subscription recovery remain required. |
| Subscription delivery loses device grant but only closes the connection | Per-frame registry check replaces pending data with one correlated null-result refusal, then terminalizes delivery; registry contention stays Busy rather than inventing revocation | Actual registry grant/revoke Rust frames decoded by Kotlin; actual event-then-revoke stream rejects publication/cache/cursor commit; gated encrypted-pipe grant/revoke subscription tests | Socket write failure can still prevent receipt delivery. Real production TCP/Android device execution remains required; admitted bytes cannot be recalled. |
| Malformed or oversized wire data | Strict JSON/frame schema, duplicate-field rejection, bounded depth/nodes/bytes, exact payload allowlists | `remote_frame`, `remote_protocol`, Kotlin source/JUnit regressions | Live TLS/frame fuzz and device tests remain open. Any parser relaxation requires paired Rust/Kotlin tests. |
| Snapshot omits a previously committed event cursor | Same-project/session publication and all display-bearing cache commits require the known event cursor to remain present; no fallback erases a saved resume position | ProjectionCommitPolicyTest and current Rust snapshot mutation in RustAndroidWireTest; ResumeStoreTest unchanged bytes and exact pending intent assertions compiled | Current encrypted-store/device/LAN recovery remains required. Initial legacy snapshots and different project/session scopes are deliberately compatible. |
| Routed connection proof treated as workspace authority | Hello/welcome/challenge have no request identity; pair/authenticate/revoke_status have only their correlation id; routing/authority/outcome fields including explicit null refuse at both frame boundaries | Rust/Kotlin six-message hostile-field matrix, shared corpus, actual Kotlin-signed pair mutations before one-use registry admission | Source/frame tests do not prove a hostile peer through the production TCP listener; connected security acceptance remains required. |
| Secret disclosure | Pairing proofs/tokens are redacted from debug output and QR contains no private key; projections expose bounded metadata/output | security/redaction and projection tests | Review new logging before release; do not collect raw host output in crash reports. |
| Path escape or destructive workspace action | Canonical path containment, ACL checks, owner/revision CAS, busy/dirty gates and durable receipts | workspace/worktree/files tests | Git/filesystem behavior varies by host. Release requires the clean/dirty and symlink cases on supported platforms. |
| Checkpoint pathname replaced between inspection and open, or FIFO lock stalls synchronization | Owner checkpoint and lock use no-follow/non-blocking opens on Unix; opened descriptors must be regular files before parsing or locking | checkpoint_file_tests descriptor/lock refusals, bounded child-process FIFO read/write test, unchanged checkpoint and CAS assertions | Parent-directory substitution and directory-fsync ambiguity are not solved by descriptor checks; supported-host and production recovery acceptance remain required. |
| Backup or uninstall leakage | Keystore aliases and encrypted metadata are excluded from backup; explicit forget/revoke flow | source backup validator and lifecycle tests | Connected Android uninstall/restore and Keystore wipe evidence is still required. |
| Missing key silently replaced or late key created after reset | Transport requires explicit identity; new key admission is foreground/fresh-invite gated and shares save/reset mutex; cancellation and generation are checked after locking | PairingCredentialAdmissionTest, explicit transport call-site compilation, LocalResetTest and LanSocketRoutingTest source | JVM tests establish coroutine ordering, not actual Keystore/device erasure. Current device execution remains required. |
| Cancelled/interrupted pairing resumes unexpectedly | Final storage reconciliation preserves committed credentials offline; explicit cancellation suppresses auto-refresh; one-use pair is never automatically retried | PairingCancelTest source and named lifecycle gates | Held storage fixture does not prove a host acceptance/network response race. Run on current APK with production desktop. |
| Cold metadata restore ignores explicit stop while loading | Initial recovery checks the same cancellation marker before automatic refresh; retains offline saved identity/display and clears queued URI without starting a connection | ScannerResultTest with/without cold URI cancellation, zero generation/null connection and later explicit confirmation assertions | Source compilation is not actual Activity/Keystore execution. A later explicit refresh, foreground transition or route change remains a separate recovery action. |
| Cancellation during handshake identity read reaches signing or local pairing success | Activity/coroutine checks bracket each identity read at admission, after welcome/challenge/signing and after receipt; original cancellation refuses next stage | PairingHandshakeTest five-read matrix and current software-P256 Kotlin/Rust pairing lane | JVM hooks are not real blocked Keystore/TLS evidence. Post-send cancellation cannot promise host rollback; current APK physical QR/LAN acceptance remains required. |
| Cancelled background read publishes after waiting for storage | Resume commit checks cancellation and captured signing identity after acquiring the shared monitor and immediately before AtomicFile publication; CAS still rejects foreground/pending/re-pair changes | ResumeStoreTest blocked-thread/pre-write cancellation regression; named desktop lifecycle receipt phase and gate | Current instrumented source compiles only. Cancellation after a non-suspending file commit is admitted cannot promise rollback; real WorkManager/device execution remains required. |
| Replaced foreground connection persists state or removes a key after storage wait | Pair/cache/workspace/revoke writes check captured coroutine/generation under store lock and before publication; host success additionally checks device identity, revoke completion checks before key removal | ForegroundStoreTest six-operation wait/final matrix and exact lifecycle phases/gates | Connected current-APK race execution remains required. Already-admitted non-suspending commits need existing reconciliation, not a claimed rollback. |
| Deep link replaces an in-flight pairing | Direct invitation admission rejects replacement while first registration/save is connecting, matching the scanner fence; cancel/background/network paths reconcile already-owned saves | PairingCancelTest held-save/deep-link regression source | Compiled regression is not a connected Activity.onNewIntent or host acceptance race result; current APK execution remains required. |
| Deep link creates a parallel Activity pairing owner | MainActivity uses singleTask and never document mode so ordinary links and document flags reuse onNewIntent admission; source and merged-release checks reject weakened task configuration | PairingActivityIntentTest actual Activity/intent source; validate_stage2_android_entry and release inspection negatives | Instrumented source compilation is not execution. Current APK must prove identical Activity/ViewModel and unchanged connecting invitation, then allow a confirming replacement. Scanner receipt requires the new named test/phase. |
| Device removal confirmation survives host replacement or scanner ownership | Revoke/forget dialogs are keyed to the full paired host; local reset state changes also retire forget confirmation. Shared device action policy disables destructive controls while scanning and fences revoke/status dispatch | DeviceActionPolicyTest JVM matrix; PairingScreenTest host/port/fingerprint/reset/scanner Compose regression; required device_confirmation_scope_verified scanner/lifecycle phase | Compose source compilation is not device execution. Current APK must prove no callback or request from an old confirmation. Explicit local reset remains distinct from host revocation. |
