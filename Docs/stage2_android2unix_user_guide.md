# Android 与 Rust 桌面局域网联动指南

状态：开发预览，2026-10-05。本文按当前源码中的命令和界面编写，不是
发布或真机验收证明。完整范围以 [Stage 2 蓝图](stage2_android2unix_blueprint.md)
为准；尚未完成的功能和验证见本文末尾。

## 1. 准备环境

工作机使用 macOS/Linux，执行 Rust、模型服务、工具、Git 和终端；Android
只负责控制及显示，不在手机上执行这些任务。手机最低 Android 12/API 31，
当前编译目标 API 35。手机和工作机需处于能相互访问的局域网；同一个 Wi-Fi
名称不代表一定互通，访客网络、AP 隔离或防火墙可能阻止连接。

在仓库根目录构建 Rust 调试版本：

```sh
cargo build --locked
```

安装了 RTK 时也可运行 `rtk cargo build --locked`，它只压缩命令输出。
桌面模型服务仍使用已有 Zenpi 配置；不要把 API key 放进二维码或 Android。
可先在本机运行 `./target/debug/zenpi config doctor` 检查配置。
配对参数可用 `./target/debug/zenpi host pair --help` 或 `-h` 查看；帮助命令
须单独使用，不创建身份文件、不加载模型，也不启动网络监听。

本地 QR/Android 联动验收不需要外部 API key：测试 harness 使用本机受控的
provider fixture，验证的是 Rust desktop 的真实配对、TLS、权限、同步和恢复
路径。只有连接真实外部模型服务时，才需要按现有 Zenpi 配置提供对应凭据；
凭据不会写入 QR、Android APK 或验收收据。

### 本机 Android 模拟器开发验证

本机已经可以直接运行 Android 模拟器，不需要把测试限制为 JVM 或源码检查。
选择专用 AVD 和明确的设备序列号，不要停止或覆盖其他项目的模拟器。
模拟器 Wi-Fi 使用虚拟网段，访问本机时使用 `10.0.2.2`；它不是工作机的
物理局域网 IP，也不能替代真实手机扫码、人工指纹核对或 LAN 验收。

自动联动验证先构建带源码归属记录的当前 Rust 和 Android 产物：

```sh
python3 tools/stage2_host_build.py
python3 tools/stage2_android_build.py
```

对已启动的专用 API 35 模拟器运行完整桌面流程：

```sh
python3 tools/stage2_desktop_android_smoke.py --serial emulator-5584 \
  --expected-api 35 --emulator-host-network --with-workspace-control \
  --with-worktree-workflow --with-doze --validation-seconds 600 \
  --receipt /private/tmp/zenpi-desktop-emulator-new.json
```

非 TUI 主机使用同一设备和产物单独验证，不与上述流程同时操作同一设备：

```sh
python3 tools/stage2_headless_android_smoke.py --serial emulator-5584 \
  --expected-api 35 --emulator-host-network \
  --receipt /private/tmp/zenpi-headless-emulator-new.json
```

该模式检查设备确为模拟器、准备模拟器 Wi-Fi、要求 ADB reverse 表为空，
在本机临时监听端口并发布 `10.0.2.2`。应用仍执行生产 LAN 路由、Keystore
和 TLS 指纹校验，没有默认网络、蜂窝网络或证书绕过。脚本使用私有测试
工作目录和受控模型响应，不代表外部模型服务验收。不要把 `--lan-ip` 与
`--emulator-host-network` 混用；前者要求设备真正能访问指定本机接口。
600 秒只约束完整测试的观察时长，二维码邀请有效期仍最多 300 秒。
每次使用新的验收文件名，保留原有失败记录。API 31/34/35 的桌面与非 TUI
同产物矩阵已通过，收据见
[api-matrix-current-20261006.json](quality/stage2_android2unix/api-matrix-current-20261006.json)。
这是模拟器 host-alias 验证，不包含实体手机、物理摄像头或签名发布验收。

Android 构建需要 Java 17、Android SDK platform 35，以及 `ANDROID_HOME`
或未跟踪的 `android/local.properties` 中的 `sdk.dir`：

```sh
cd android
./gradlew :app:test :app:assembleDebug
```

回到仓库根目录，连接目标 Android 设备，明确选择设备序列号后安装：

```sh
adb devices
adb -s DEVICE_SERIAL install -r android/app/build/outputs/apk/debug/app-debug.apk
```

应用包名是 `app.zenpi.android`。这里的 APK 是开发调试包；仓库中的旧构建
产物不一定包含当前源码，不能直接当作本轮构建结果。正式签名发布仍未完成。

## 2. 启动同一会话的桌面与配对二维码

以下示例从仓库根目录运行。`WORKSPACE` 必须是本机真实工作目录，
`SESSION` 是该工作目录对应的会话 journal。使用已存在的会话时，先退出
另一个正在写同一会话的 Zenpi，不要启动两个独立执行器共享一个 journal。

```sh
WORKSPACE=/absolute/path/to/project
SESSION=/absolute/path/to/project-session.jsonl
./target/debug/zenpi host pair --desktop --workspace "$WORKSPACE" --session "$SESSION"
```

此命令启动生产 Rust TUI 和它自己的远程监听器，首次显示全屏二维码。
默认自动选择本机局域网地址和空闲端口。二维码包括地址、端口、主机证书
指纹、一次性令牌和过期时间，不含模型服务凭据。默认邀请有效期 300 秒；
`--duration-seconds` 可设为 1..300 秒。

多网卡地址选择不明确时，指定手机可达的本机接口地址。例如：

```sh
./target/debug/zenpi host pair --desktop --workspace "$WORKSPACE" --session "$SESSION" --bind 192.168.50.14:7777
```

把示例 IP 换成本机实际地址。`127.0.0.1` 不是手机可访问的工作机地址；
`0.0.0.0` 只表示监听所有 IPv4 接口，不应当作为手机连接地址。
使用通配监听时可增加 `--advertise 192.168.50.14`，但明确绑定某个 IP 时，
advertise 必须与它相同且地址族一致。固定端口被占用时需换端口。

在有多个本机接口时，建议先用直接 LAN smoke harness 验证发布地址和 TLS
路径（它不会使用 adb reverse）：

```sh
python3 tools/stage2_android_pair_smoke.py --serial DEVICE_SERIAL \
  --lan-ip 192.168.50.14 --with-host-state
```

将 `192.168.50.14` 换成工作机实际的 RFC1918/ULA 地址。此命令要求设备和
工作机互通、adb reverse 表为空，并且只接受 literal 私有地址；它仍不能替代
实体手机相机扫描或跨 AP/防火墙的物理网络验收。未提供 `--lan-ip` 时 harness
才使用 adb reverse，仅证明 emulator 与 host 的 TLS/协议互操作。

在桌面二维码视图按 `r` 使旧邀请失效并生成新邀请；按 `Esc` 取消尚未使用
的邀请并回到普通桌面 TUI。桌面模式下，已注册设备仍可连接，直到桌面
进程退出。邀请过期不等于已经授予的设备权限被撤销。
邀请过期后，桌面会移除二维码并显示 `Invitation expired`，可按 `r` 刷新，
不会因为过期而退出正在运行的桌面。若主机时钟不可读则显示
`Host clock unavailable`，不显示二维码；修复时钟后重新生成邀请。
时钟向后跳变导致邀请超出允许窗口时显示 `Host clock changed`，同样不显示二维码。
终端空间不足时显示所需列数和行数，扩大窗口后再扫码。文字可以换行，
二维码本身不会换行或裁切，以免生成看似可扫但内容不完整的图案。
回到普通桌面后，空闲时按 `F3` 可生成新邀请并重新打开二维码，用于
再次扫码或配对第二部手机；沿用同一个监听地址和主机身份，不创建另一个
会话执行器。工作运行或排队时此入口拒绝；结束后再试。普通、未开启
远程联动的 TUI 不会因 F3 启动监听器。

## 3. 手机扫码与核对

1. 打开 Android 应用，点击 `Scan QR`，允许相机权限并扫描桌面二维码。
2. 核对手机显示的主机地址及 `Host SHA-256` 指纹与桌面一致，点击 `Confirm host`。
3. 等待注册完成。扫码即桌面确认：二维码只显示在工作机自己的屏幕上，且是
   一次性、最长 300 秒的邀请。配对成功后，设备立即获得所挂载项目
   （`--workspace`）的 Read、Control 和 Approval，可直接发送任务和处理审批。
   没有挂载项目时（不带 `--workspace`），配对只注册设备，手机显示不可控制。

不要分享二维码截图、完整邀请 URI 或令牌：持有二维码即可配对并获得控制权。
证书指纹变化、邀请过期或已使用时不要绕过验证；回到桌面检查，再生成新的
邀请。若自己的手机提示邀请已被使用而桌面 `Accepted` 计数增加，说明有人
抢先扫码，立即用下一节的设备列表找到并撤销该设备。
失败后可能已注册但手机没收到回复，先用下一节的本机设备列表检查。

邀请过期、重置或存在待处理请求时不能确认。
手机也按单调时钟计时，休眠时间计入有效期；调回系统时间不会重新启用已经
过期的邀请。出现过期或时钟异常后，在桌面刷新二维码并重新扫码，不使用
修改手机时钟的方法继续旧邀请。
工作机在接收配对请求时也检查有效期窗口。主机观察到邀请过期、时钟不可读
或回拨超出允许窗口后，会废止该邀请；修复时钟后须按 `r` 刷新，再扫码。
错误的令牌或指纹不会消耗仍有效的邀请，但不能用它绕过时钟或有效期检查。
若手机设备密钥丢失或与已配对身份不匹配，自动同步会停止，旧控制权限会
关闭，但离线消息和未决请求不会被清除，也不会自动生成新身份。先在桌面
核实未决任务及设备状态，再按需要撤销旧设备并重新配对。

工作机局域网地址或端口变化后，重新生成邀请并扫码核对。只有主机证书
指纹和手机设备 ID 都未改变时，重新配对才保留原有离线消息、子标签显示
和同步游标；这些缓存不授予控制权限，仍需重新认证读取主机状态。
不同主机身份或不同设备 ID 不继承原缓存。无效二维码不会丢掉当前已配对
状态；取消新的配对确认会恢复原主机的离线显示。未决任务或撤销请求必须
先解析，不能通过重新扫码清除。

## 4. 在工作机查看与撤销设备

保持桌面进程运行，在另一个本机终端从仓库根目录执行：

```sh
./target/debug/zenpi host pair --list-devices
./target/debug/zenpi host pair --list-devices --json
./target/debug/zenpi host pair --workspace "$WORKSPACE" --session "$SESSION" --list-projects
```

手机配对成功后在 `Device ID` 下显示完整设备 ID，复制图标复制该 ID，
离线时也可核对。将它与本机设备列表中的完整 ID 对照，不要只凭默认
名称 Android 或列表位置选择设备。设备列表提供设备 ID、名称和撤销状态；
加 `--json` 会额外列出当前 capabilities、projects 和 revision，不含密钥。
项目列表以 JSON 提供稳定项目 ID、本机目录和当前选择。项目列表是本机只读
检查，不启动监听器、不初始化模型服务、不创建主机身份或权限。

配对授予的是扫码时挂载的项目。已配对设备扫描挂载另一个项目的新二维码，
会在原有项目之外追加该项目；同一项目重复扫码不改变注册表。不再提供
单独的授权命令。撤销设备：

```sh
DEVICE_ID=DEVICE_SHA256_ID
./target/debug/zenpi host pair --revoke-device "$DEVICE_ID"
```

撤销在该设备的下一帧生效，正在进行的连接随即被拒绝；被撤销的设备
即使再次扫码也不会恢复，需换新设备密钥重新配对。

若启动时使用自定义 `--identity PATH`，设备列表和撤销也必须使用
同一个 `--identity PATH`。默认是 `$HOME/.zenpi/remote/identity.json`，设备
注册表在同目录的 `identity.devices.json`。不要更换身份文件来绕过撤销。

## 5. 使用与同步

同步尚有回放尾部时，手机显示 `Catching up`；主机因回放缺口或分支变化
要求替换、且手机已验证新快照后，会显示 `Snapshot replaced`。这是本次
在线读取状态，不是离线缓存的授权，也不代表未决任务已经成功。

手机显示主工作区标签及目录/worktree 子标签；有对应权限时可以选择、
重命名、移动或关闭子标签，并通过确认对话框操作 Git worktree。实际
文件系统和 Git 操作始终发生在工作机，失败不会静默删除持久化标签。

有 Control 权限时可在输入框发送任务。接受请求只表示已进入执行流程，
不是任务成功。按请求 ID 查看 accepted/running/succeeded/failed/cancelled/
unknown 状态；输入无效、资源限制等失败有固定诊断标签。任务运行时的
流式预览不是持久化聊天消息，离线缓存不保留这种预览。

手机发起的 worktree 任务也可在桌面通过 `/cancel` 或普通中断操作请求
取消。只作用于当前项目中已同步选中的子标签，包含该标签内运行和排队
的任务，不会取消其他子标签。桌面显示“请求中断”不代表任务已经退出；
若有请求未被接收，可以再次请求，不能通过重发原任务来替代取消。
手机仍通过原请求 ID 查看实际最终状态，桌面草稿及原任务接受记录保留。

桌面 `/status` 会同时显示主会话状态及当前子标签最近最多 32 个 worktree
任务的设备、请求 ID 和执行状态。`runtime active` 表示控制器仍追踪该任务，
不等同于成功；结果不确定时仍可能显示该标记。重启后只有旧运行记录的
任务显示 `unknown_outcome`，不会推断它仍在执行，也不会自动重发。

手机上的任务即使显示“结果不确定”，只要主机仍确认原任务运行中，也会
显示运行标记并保留取消按钮。没有活运行证据的旧记录不会提供取消入口；
取消仍需要当前权限和前台网络连接，不会重新提交原任务。

手机摘要最多显示 16 条任务，仍被主机追踪的任务优先于旧终态；刚接受的
任务在首次状态轮询前也会显示为已接受。任务列表窗口可按主机快照分页，
用前后箭头查看；快照变化时需刷新，不把首页摘要当作全部任务清单。
分页中的活任务可使用停止图标请求取消；页面加载、失效或离线时不可用。
主机确认已结束的摘要状态优先于旧页面。任务结果未知时，只有主机仍提供
活运行标记才显示取消入口。后续列表页的已完成任务也可通过展开或阅读
图标查看完整输出与历史；按页读取，关闭消息可回到原历史页。工作区、
主机会话或权限变化时会关闭读取，旧页面不能被用来恢复控制权限。

文件选择器浏览的是当前桌面子标签内的文件，不是上传手机文件；选择只
把 `@"path with spaces"` 引用插入草稿，仍需显式发送。已知凭据路径不会
作为远程附件提供，但这不是任意文件内容的完整秘密识别。资源选择器
同样只插入草稿，技能和模板由工作机执行。任务进行中，steering 为纯文本，
不读取附件或执行新的 slash 命令。

资源窗口会在主机授予控制权限时显示重载图标。它只重载工作机已经选择的
资源目录，不接受手机提供的新路径。成功后重新打开资源窗口读取新目录；
离线、任务运行中或存在未确认写请求时不能开始新的重载。若结果不确定，
保留并检查同一请求，不要反复新建请求。完整资源路径管理尚未实现。

Diff 窗口可用前后箭头逐页查看补丁，保留最近七个前页；更早内容需刷新
从头读取。主机文件变化时旧分页失效，必须刷新，不拼接两次不同变更。
总补丁最多 1 MiB，目录未跟踪文件和状态也有上限；显示 `Diff truncated`
时不代表已查看全部变更。旧主机只提供摘要时没有下一页。读取不修改文件，
手机应用或撤回补丁尚未实现。

模型/推理设置来自工作机；可用选择由实际后端能力决定。更改需明确提交，
运行中或修订冲突时拒绝，不应通过新请求反复覆盖本机用户的选择。
主标签中的 New session 图标经确认后在工作机新建空会话，旧对话保留。
需要 Control 权限，并在主子标签、空闲且没有待确认请求时操作。结果不
确定时核对同一请求，不要连续新建。历史会话恢复及重命名的源码入口和
当前验收边界见下方“历史会话”。

长消息可在 Message 窗口逐页读取，上一页箭头可回看最近七页；超过保留
范围时关闭并重新打开，从首段重新读取。页面只临时保留，不写入离线
消息缓存；工作区或消息变化、后台和权限失效会关闭阅读窗口。
普通会话中的工具调用可用展开图标查看完整脱敏参数，按页阅读并回看最近
七页；它是只读查看，不会再次执行工具。参数页不会写入离线缓存，调用
或会话变化后必须重新打开。
审批需要 Approval 权限（扫码配对时随所挂载项目一起授予），Allow/Deny 为单次决定，不建立永久工具授权。
Diff 和当前终端输出为有界显示。桌面 Shell 尚未打开时，Control 设备可用
终端图标明确打开当前桌面子标签的 Shell，仍在工作机上运行。任务运行中、
会话/子标签变化或有其他不匹配 Shell 时拒绝；未知结果须核对原请求，
不能靠重复打开来判断成功。此入口不接受手机指定 shell 或工作目录。
桌面已打开匹配 Shell 时，Control 设备
可发送终端输入、特殊键和窗口尺寸；手机不会另起 shell。勾选 Enter 时
发送末尾附带回车，不勾选可向正在运行的程序发送部分输入。输入成功只
代表主机接收字节，不代表命令执行成功，须查看输出。结果不确定时保留
同一请求核对，不能新建输入重发。完整终端仿真尚未实现。
终端保留主机换行，长行可横向滚动。键盘图标菜单包含退格、删除、行首/
行尾、翻页、Insert、Ctrl+D、Ctrl+Z、Ctrl+A/E/L；这些键发送到现有主机
程序，Ctrl+D 可能结束输入或 shell，Ctrl+Z 可能挂起程序，不是手机本地操作。
Rows/Columns 跟随主机实际尺寸；普通输出更新保留未提交尺寸，主机尺寸
变化会更新尺寸字段。切换终端或 tab 后滚动位置重置。
Shell 退出后显示 `Terminal exited`，最后输出仍可读，旧输入和尺寸控制
不再可用。使用终端图标可明确重新打开当前子标签的 Shell，实例 ID 会变化；
旧请求的核对只解析旧结果，不会把命令发送到新 Shell。退出不会自动重启。
终端旁的阅读图标可查看主机仍保留的历史并前后翻页，最近七页可回看。
若输出变化导致续页冲突，用刷新图标从头重读；已淘汰的输出不能恢复。
终端历史只临时保留，不写入离线缓存。输出脱敏并非完整秘密识别，shell
换行或光标重绘可能拆开秘密标记；仅给可信设备开放终端读取权限。
终端输入使用桌面用户的 shell 权限，能够执行命令并修改文件；只给可信
设备授予 Control，不可信设备应保持 Read。工具审批不拦截这种直接输入。
手机 Diff 不提供已知凭据路径的内容，目录审阅也会排除这些文件的变更；
桌面本地 Diff 不受这一远程过滤影响。普通文件名中的秘密内容仍需审阅，
不能把路径过滤当作完整的秘密识别。

## 6. 断线、未知结果与撤销

后台、Doze、进程死亡或网络变化可能关闭手机连接；在工作机仍运行时，
已经接受的任务可继续。回到前台或点击 `Refresh host` 后通过认证、游标
回放或有界快照恢复。离线显示可能过时，不授予写权限；后台任务不是
永久连接保证。

出现 `Retry same request` 时，它解析保存的原请求结果，使用相同请求 ID
和内容，不是创建一个新的任务。不要再次手动发送相同内容来代替它。
手机连接操作自身超时会退出加载并显示失败或未知结果；只读同步可按退避
重新连接，未确认写入和撤销仍保留原请求。配对超时不表示邀请未被使用，
先检查桌面设备列表，不要当作一次确定失败而重复操作。
只读同步连续失败时，自动重连的等待时间会随机变化，退避上限逐步增至
60 秒；成功同步后重置。网络恢复或显式刷新会重新开始连接，不会自动
重新提交未确认的任务。
手机上的 `Cancel` 只停止当前连接，不忘记配对主机；离线消息与游标仍保留，
实时预览和控制权限会移除。之后使用 `Refresh host` 可重新认证并恢复同步，
无需重新扫码或重启应用。未确认写入和撤销仍保留原请求，不因取消而变成
成功。删除手机密钥、缓存和待解决请求须使用单独的 `Forget device locally`。
收到主机明确的权限拒绝或所有者变更后，手机保留离线消息和游标，但清除
旧审批、取消、steering 及其他控制权限。检查桌面权限后用 `Refresh host`
重新认证；这不会自动删除手机密钥，也不会把未决写入当作已完成。
若原项目已关闭或不再授权，手机停止该次自动读取并清除旧控制权限，保留
离线消息。下一次 `Refresh host` 会重新读取当前授权项目，不反复请求旧
项目；这不表示整个设备已经撤销，也不会自动解决原项目的未决任务。
`unknown_outcome` 表示无法确定执行结果，不表示可以安全重做副作用；
应检查桌面状态、文件和 journal。忘记本地数据会删除未解决请求记录。

撤销访问可在手机使用 `Revoke device on host`，或在工作机执行：

```sh
./target/debug/zenpi host pair --revoke-device "$DEVICE_ID"
```

手机撤销未确认时使用 `Check revocation status`；不要把网络失败当成撤销
成功。`Forget device locally` 只删除手机密钥、缓存和待解决请求，不撤销
工作机上的权限。丢失手机时先在工作机撤销设备，再处理本地数据。

## 7. 排障与当前边界

### 历史会话

`Browse conversation` 查看当前会话的较早消息，不限于首页最近 64 条。按页
浏览时，可展开长消息或工具参数。桌面新增消息或切换分支后，旧页会关闭或
拒绝继续翻页，需要重新打开或刷新。浏览不切换会话、不执行命令；离线时
不可继续读取。这条路径已接入源码，仍需当前 APK 的连接设备验收。

主项目子标签可通过 `Browse sessions` 查看桌面保存的历史会话，按页切换，
选择旧会话后确认恢复。当前会话不可重复恢复；旧对话不会因此删除。
桌面忙碌、存在待处理输入或工作树任务时会拒绝切换。目录或会话变化导致
列表失效时，用 `Refresh sessions` 重新读取，不使用旧列表继续操作。
列表中的 `Search sessions` 可按会话名字、ID 或对话正文搜索，点击搜索图标
提交；清空搜索框再搜索会返回完整列表。搜索由桌面主机执行，正文仅匹配
脱敏后的用户和助手消息，显示匹配数量及最多四条短摘要，不搜索工具参数
或系统消息。搜索、翻页不改变当前会话；恢复仍需要单独确认。离线时不可搜索。
切换列表页会清除尚未确认的恢复选择，需要在目标所在页重新选择并确认。
结果未知时保留并检查原请求，不再次创建新的恢复请求。
这部分已接入源码，但当前 APK、真实摄像头扫码及 LAN 会话切换尚未验收。

当前主会话也可通过 `Rename session` 编辑名字并确认。最多 64 个 UTF-8
字节，不接受空白名字、控制字符或路径分隔符；主机还会拒绝已使用的名字
及敏感文本。修订冲突时先刷新再作新选择。结果未知时检查原请求，不再次
改名来代替确认。历史会话名在线显示，不作为离线权限或当前状态的证明。

桌面或另一客户端切换同一项目的会话时，已连接手机可重新认证并读取新
会话快照，不沿用旧会话游标。该自动刷新只用于前台且没有未决写入/撤销
的只读订阅；权限丢失或真实 owner 冲突仍需明确检查和刷新。当前源码已
实现此行为，真实设备同步仍需验收。

| 现象 | 检查与处理 |
|---|---|
| 扫码后没有项目 | 主机未挂载项目：用 `--workspace`/`--session` 启动后重新扫码，再 Refresh host |
| 无法连接 | 确认桌面仍运行、IP/端口、AP 隔离、防火墙、Wi-Fi/Ethernet 路由；网络或端口变化后需新邀请 |
| 邀请无效/过期 | 检查工作机和手机时钟，桌面按 r 刷新；不要重复使用已消费令牌 |
| 指纹不一致 | 停止配对，核对是否连到正确工作机；不禁用证书校验 |
| busy/修订冲突 | 等待本机操作完成，刷新状态，再作新的明确选择 |
| 文件/资源页面失效 | 刷新或重新打开；当前子标签或目录内容可能已经变化 |
| 本地凭据不可读 | 检查桌面撤销状态；确认后 Reset local device 并重新扫码，不改写损坏密文 |

MVP 为 LAN-first，不提供任意 NAT 穿透、公网 relay 或永久后台连接。 
手机可调整工作树的 1..64 并发配额。已有任务运行时，主机应用新调度配额
并提交配置后才确认；降额不取消正在运行的任务。结果未知时保留原请求，
使用明确的同请求重试确认，不根据显示值推断成功。完整设置及交互式 PTY 尚未完成。
API 31/34/35 当前 APK 的相机扫码、真实 LAN、
断线恢复、迁移/备份/卸载测试与签名可复现发布仍需完整验收。

补齐同一会话的回答，保存匹配缓存并推进游标，且消息不能重复。
手机通过实际输入框发送测试消息，并显示 Desktop 本地 provider fixture 的回答；

### 配额提交结果未知

若配额变更已保存意图但最终提交未确认，同请求重试保持未知，不自动重做。
先停止原主机，再在本机检查待确认记录：

```sh
./target/debug/zenpi host pair --workspace "$WORKSPACE" --session "$SESSION" --list-quota-intents
```

核对设备、请求及配额后，明确接受该配置用于后续启动：

```sh
./target/debug/zenpi host pair --workspace "$WORKSPACE" --session "$SESSION" --reconcile-quota "$REQUEST_ID" --device "$DEVICE_ID"
```

此操作不启动 worker、不重放调度命令，也不开放网络监听。旧运行器租约仍被
占用或主机状态已变化时会拒绝，不能据此宣称运行中配额已生效。
